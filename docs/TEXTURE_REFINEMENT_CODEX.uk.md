# Як довести текстури через Codex

Paint створює початковий UV-атлас. Розмиті шви, плями й неточні пряжки можна покращити через агента. Цей workflow виконується окремо від майстерні: потрібні Blender/Python і доступний у вашій сесії інструмент AI-редагування зображень. Якщо такого інструмента немає, агент має чесно повідомити та виконати доступне ручне/процедурне очищення або пояснити потрібне підключення. Сам репозиторій не містить API ключів чи вбудованого платного image editor.

## Принцип

Не перемальовувати UV-атлас як звичайну картинку: AI пересуває UV-острови, шви й деталі. Надійніший метод — незмінний 3D mesh → калібровані ракурси → очищені 2D-ракурси → видима проєкція кольору назад у той самий UV. Геометричну пряжку чи відсутню складку колірна правка не відновить: це окреме редагування mesh.

## Промпт агенту

> Прочитай AGENTS.md і docs/TEXTURE_REFINEMENT_CODEX.uk.md. Візьми textured.glb, шлях: [мій шлях]. Збережи вихід без змін. Покращи лише base-color texture: прибери плями й трикутні дефекти, збережи форму, UV, палітру, шви та зношеність. Спочатку створи front/side/back/3⁄4 рендери на незмінній геометрії, збережи матриці камер, depth і UV-дані. Відредагуй потрібні ракурси доступним image editor, перевір їх і спроєктуй кольори назад у старі UV з перевіркою видимості. Збережи новий GLB окремо, створи before/after preview і переліч невиправлені дефекти.

## Робочий порядок

1. Створи окрему папку refinement із source.glb та оригінальним атласом; перевір UV, матеріал, polycount, осі й масштаб. Не перезаписуй результат Paint.
2. Blender: завантаж mesh, вимкни анімацію й деформації, зафіксуй позу. Зроби ортографічні front, left/right side, back, 3⁄4, а для дрібних деталей — близькі кадри. Для кольорових правок використовуй albedo/emission без запеченого студійного освітлення.
3. Збережи камери, intrinsics/orthographic scale, extrinsics, vertices, faces, UV на loops, normals, depth або face/position buffers. Не змінюй їх до зворотної проєкції. Preview майстерні є оглядовим contact sheet, а не каліброваним входом для проєкції: з нього не можна точно відновити камери.
4. Редагуй окремі зображення: «прибери тільки плями; збережи камеру, кадрування, силует, колір, пряжки й шви». Не проси одночасно змінювати форму, позу та текстуру. Переглянь AI-вихід; якщо деталі перемістилися чи зникли — відхили його.
5. Проєкція: для кожного UV-текселя знайди точку surface через barycentric coordinates. У кожній камері перевір кадр, z-buffer/depth і facing normal, потім збери колір із видимих views. Невидимі поверхні лиши оригінальними. Змішуй views за facing/visibility та плавними масками; не переносити фон на краї об'єкта.
6. Padding UV роби в межах коректних островів. Прогалини заповнюй за 3D-близькістю й нормалями тієї самої поверхні, а не простим сусідством атласу. Зберігай непокриті приховані ділянки.
7. Прив'яжи нову texture до вихідних UV, експортуй `refined.glb`. Порівняй front/3⁄4/side/back, шви та zoom деталей; програмно перевір незмінність vertices/faces/UV, читання GLB й texture dimensions.

## Якщо спрощуєш mesh

Decimate може зробити стару texture невідповідною новим UV. Збережи щільний оригінал; за потреби створюй UV low-poly і роби selected-to-active bake base color (EMIT), перевір cage/ray distance/padding. «2048px» після rebake не додає деталей до початкової 1024px карти. Retopology, normal map і LOD — окремі етапи.

## Повторний Paint

Якщо хочеш перетекстурувати той самий mesh через майстерню, вибери готовий shape або завантаж свій GLB у Paint-форму, додай front/side/back і постав Paint у чергу. Нова генерація геометрії не потрібна. Paint може перебудувати UV; це окремий новий результат, не локальна правка старого атласу. Просте повторення чи збільшення resolution не гарантує кращої відповідності референсам.

## Що попросити у звіті

Шляхи source/refined/preview, інструмент редагування (без вигаданої назви моделі), розмір texture, час, coverage проєкції, що збережено, видимі дефекти й неперевірені ділянки. Не підміняти перевірку результату самим фактом успішного експорту.
