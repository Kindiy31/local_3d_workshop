# Local 3D Workshop

**Фото → mesh → текстурований GLB. Локально, з автоматичною чергою.**

| Етап | Модель | Вхід | Результат |
| --- | --- | --- | --- |
| Геометрія | Hunyuan3D-2mini Turbo | Одне фото | `shape.glb` |
| Геометрія з трьох ракурсів | Hunyuan3D-2mv | Front / left side / back | `shape.glb` |
| UV і текстура | Hunyuan3D Paint v2.0 | Mesh + три фото | `textured.glb` |

[Встановлення агентом](docs/INSTALL_AGENT.uk.md) · [Доведення текстур](docs/TEXTURE_REFINEMENT_CODEX.uk.md) · [Результати перевірок](VALIDATION.md)

Локальна майстерня 2D → 3D: вебформа українською, збережена GPU-черга, генерація геометрії, UV і текстури, GLB та preview у чотирьох ракурсах. Референси та результати зберігаються на вашому ПК. Під час встановлення завантажуються залежності й моделі; генерація використовує локальні ваги.

## Встановлення через агента

Клонуйте репозиторій або завантажте ZIP через **Code → Download ZIP**:

```powershell
git clone https://github.com/Kindiy31/local_3d_workshop.git
cd local_3d_workshop
```

Відкрийте цю папку в Codex і надішліть:

> Прочитай AGENTS.md і docs/INSTALL_AGENT.uk.md. Перевір мій ПК, WSL, GPU, CUDA, RAM і диск. Встанови Local 3D Workshop за інструкцією, повторно використовуючи наявне середовище та кеш, якщо вони сумісні. Не скидай мої середовища. Запусти doctor, перевір вебформу й чергу. Покажи адресу майстерні та чесно повідом, які етапи ще не перевірені.

Агенту потрібні доступ до термінала, WSL і мережі. Перезавантаження, права адміністратора, прийняття сторонніх ліцензій або Hugging Face login можуть потребувати вашої участі. Завантаження репозиторію саме по собі не встановлює моделі.

Детальна інструкція: [встановлення](docs/INSTALL_AGENT.uk.md). Після встановлення Windows: `powershell -ExecutionPolicy Bypass -File .\Start-Local.ps1`; Linux/WSL: `bash run.sh`. Адреса: <http://localhost:7861>.

Зупинка вебслужби: `powershell -ExecutionPolicy Bypass -File .\Stop-Local.ps1` або `bash stop.sh`. Уже запущені GPU-завдання продовжуються.

## Як користуватися

1. Одне фото: Hunyuan3D-2mini Turbo, 5 кроків. Три ракурси: Hunyuan3D-2mv, 30 кроків.
2. Для режиму трьох ракурсів завантажте front / left side / back одного елемента з однаковою позою та масштабом. Бічний ракурс бажано 90°. Непослідовні AI-референси можуть спричинити розбіжності форми.
3. Позначте «Одразу після mesh запустити Paint». Черга створить окремі mesh і Paint завдання; Paint використовує ті самі три фото. Або окремо завантажте свій GLB і три референси у форму Paint.
4. Одночасно працює лише одне GPU-завдання. Черга переживає перезапуск вебслужби. Якщо mesh завершується помилкою, залежний Paint не запускається.
5. Завантажте `shape.glb`, `textured.glb`, `preview.png`, `metrics.json`. Дані: `runtime/jobs/<ID>/`. Зберігайте сирий mesh окремо.

Невідома тривалість 2mv не перетворюється на вигадану ETA. Сервісні відсотки означають етапи. На контрольному GTX 1060 6 GB FP16/offload запуск 2mv займав приблизно 2,5 години, Paint з трьох фото — близько 3 годин; інші об'єкти й ПК можуть суттєво відрізнятись. 6 GB — перевірений повільний профіль цього wrapper, а не загальна гарантія Hunyuan. Рекомендовано 32 GB RAM і достатньо вільного SSD; перевіряйте потребу моделей перед встановленням.

## Доведення текстур через Codex

[Метод і готові промпти](docs/TEXTURE_REFINEMENT_CODEX.uk.md): рендери на незмінному mesh → AI-правка ракурсів → проєкція кольору назад у ті самі UV. Пряма AI-перемальовка UV-атласу часто руйнує острови. Інструмент автоматичної AI-корекції в цю вебформу не вбудований: роботу виконує агент із доступними інструментами редагування зображень та Blender/Python.

## n8n — необов'язковий

Майстерня й черга працюють без n8n. За бажанням встановіть n8n окремо, створіть власний обліковий запис, імпортуйте `n8n/workflow.json` і активуйте workflow. У `.env` увімкніть `HUNYUAN_N8N_WEBHOOK`. Для n8n у Docker адреса сервісу має бути доступною з контейнера: `127.0.0.1` усередині контейнера не означає ваш хост. Паролі та база n8n не постачаються.

## Перевірки й межі

Перевірки без генерації, через Python встановленого Hunyuan venv:

```bash
python check_queue.py
python check_api.py
python check_server.py
```

Не використовуйте випадковий системний Python: активуйте відповідне середовище або викликайте його Python абсолютним шляхом. `doctor.py` додатково потребує `PYTHONPATH` на upstream, див. інструкцію встановлення.

`check_queue.py` перевіряє чергу без GPU. `doctor.py` перевіряє імпорти, CUDA й наявність ваг. Повний mesh/Paint smoke run на новому ПК потрібен окремо. CPU-only, macOS/MPS та нові GPU, несумісні з PyTorch 2.4.1/CUDA 12.1, цим профілем не підтверджені; агент має підбирати й перевіряти сумісний стек, а не приховувати помилки.

Не запускайте кілька uvicorn workers чи копій сервісу з однією папкою runtime: черга розрахована на один процес сервісу. За зависання логів перевірте процес, CPU і `nvidia-smi`; 0% GPU під час UV inpaint може бути нормальною CPU-обробкою.

AI-вихід потребує очищення, ретопології, ригу, LOD та перевірки матеріалів у цільовому рушії. n8n monitoring failure не зупиняє GPU-задачу. Вебслужба слухає лише localhost; не публікуйте її напряму в Інтернеті без автентифікації та обмежень завантажень.
